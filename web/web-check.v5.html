⚠️ The Brutal Truth: Client-Side Limitations

Let's be clear about what this library is—and what it isn't.

SpamWarden.js acts as an intelligent, frictionless frontend shield and early warning system. It is highly effective at stopping automated browser bots, scripts, and low-effort copy-paste spammers from polluting your forms.

However, client-side JavaScript cannot protect your backend from dedicated attackers. A competent threat actor can simply inspect network traffic, extract your endpoint, and fire direct POST requests to your server, completely bypassing the browser.

Running a WordPress site? You need server-side enforcement. Get SpamWarden WP (Early Access) →

Why use this JS version?

It is the ultimate Threat Intelligence Sensor. Deploying this snippet gives you instant visibility into frontend attack vectors, allowing you to monitor telemetry in your SIEM without exposing your primary database to raw spam.

Privacy-First: Auto-DLP & PII Masking

To ensure compliance when monitoring forms, data never leaves the browser unmasked. The engine automatically strips and tags Credit Cards, Emails, and Phone Numbers before sending telemetry.

The sdFlag Telemetry Matrix

Mode Input Condition Action Triggered PII Handling
0 (Spam Only) Clean Message (No PII) Ignored -
0 (Spam Only) Clean Message + PII Ignored -
0 (Spam Only) Spam Message Reported via Beacon Masked (Always)
1 (DLP Audit) Clean Message (No PII) Ignored -
1 (DLP Audit) Clean Message + PII Reported (DLP Alert) Masked (Always)
1 (DLP Audit) Spam Message Reported via Beacon Masked (Always)

Use Case: Set sdFlag = 1 if you need an audit trail of users attempting to submit sensitive PII into unencrypted or public-facing forms.
